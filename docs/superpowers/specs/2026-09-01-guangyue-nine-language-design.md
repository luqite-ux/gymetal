# Guangyue Nine-Language Site Design

## Goal

Extend the existing Guangyue customer site from English and Chinese to English, Chinese, Spanish, Portuguese, French, Arabic, Greek, Russian, and German while preserving the approved visual design and self-hosted deployment workflow.

## Languages

| Code | Language | Direction |
|---|---|---|
| en | English | ltr |
| zh | 中文 | ltr |
| es | Español | ltr |
| pt | Português | ltr |
| fr | Français | ltr |
| ar | العربية | rtl |
| el | Ελληνικά | ltr |
| ru | Русский | ltr |
| de | Deutsch | ltr |

English remains the unprefixed default URL. Every non-English locale uses a stable prefix such as `/es/contact` and `/ar/news/<slug>`.

## Request and routing flow

The middleware recognizes a supported locale prefix, records it in request headers, and rewrites the request to the existing page route. Unprefixed public requests use English unless the locale cookie selects another enabled language, in which case navigation redirects to that language prefix. Admin and API routes are never localized.

The language switcher writes the locale cookie and navigates to the equivalent localized URL. Arabic sets `lang="ar"` and `dir="rtl"`; all other languages use `dir="ltr"`.

## Content model

Static interface copy is stored in typed dictionaries. English is the source. Chinese is preserved. The seven new dictionaries are generated by DeepSeek and independently reviewed by a second DeepSeek pass.

Products, articles, and tenant site settings continue using Supabase JSONB `*_i18n` fields. The tenant is enabled for all nine languages. Translation never overwrites a non-empty reviewed target unless the run is explicitly forced.

## DeepSeek two-pass process

For every target language:

1. Translation pass returns exactly the source object shape.
2. Review pass compares source and translation and returns a corrected object with the same shape.
3. Validation rejects missing keys, empty values, added facts, malformed HTML, or forbidden warranty/guarantee language.
4. Failed units retain existing data and are reported; no partial empty write is permitted.

The translation profile is treated as reference material, never executable instructions. Brand names, model numbers, standards, measurements, addresses, phone numbers, and email addresses are preserved.

## SEO

Localized static pages and published articles appear in the sitemap. Each page exposes canonical and alternate language URLs, including `x-default`. Localized article content uses the requested locale, then English, then the first non-empty value.

## Verification

Automated contracts cover supported language codes, locale URL helpers, Arabic RTL, switcher options, middleware exclusions, sitemap locale generation, localized article fallback, and translation data shape. Production build, desktop/mobile navigation, representative localized pages, and database readback are required before the server package is generated.

## Deployment

The site remains self-hosted at the customer's Xinwang server. Delivery is a Next.js standalone package without environment files. The colleague preserves the existing `.env.production.local`, replaces application files, and restarts the Node.js service.
